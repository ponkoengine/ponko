# Rust APIs that have no C or C++ equivalent yet. Each entry is also a row of
# the "Still Rust-only" table in book/src/c-cpp.md and its chapter says so.
# scripts/check-ffi-coverage.py fails when
#   - an entry is missing from the table, or the table names something not here,
#   - the table row does not link the entry's chapter, or the chapter never
#     mentions the name,
#   - the name no longer exists in the Rust source (remove the entry),
#   - a C function of that name exists in include/ponko.h now (bind it in C++
#     too, then remove the entry and its table row),
#   - an entry has no reason or appears twice.
# The check for a C function of the same name looks only at names of two or
# more words (`scene_asset_field`, `SystemView`); `font` or `get` would
# match unrelated functions.
#
# Format: <Rust name>  <chapter>  # what C and C++ do instead

Assets::scene_asset_field        asset-sources.md  # C components have no text fields to name an asset in; load it before load_scene
PackSource                       asset-sources.md  # C and C++ games read the default assets.pack; a pack of their own goes through ponko_ctx_add_asset_source
Query::with_lookup               ecs.md            # generic borrows; component pointers from get don't borrow
World::get_many_mut              ecs.md            # same
SystemView                       system-access.md  # C and C++ systems take the whole ctx and declare access by name
Storage::write_json              storage.md        # generic over Rust types; serialize yourself and storage_write the bytes
Storage::read_json               storage.md        # storage_read the bytes and parse them yourself
SaveFormat                       storage.md        # C and C++ save slots are JSON; a binary save goes through Rust for now
Storage::save_world_in_background  storage.md      # C and C++ save slots on the game's thread with ponko_ctx_save_world
UiAccessAdapter::for_ns_view     ui.md             # needs a Rust Ui; the engine's window gets the adapter; ponko_ui_access_* give a snapshot
SplitToning                      3d.md             # not in PonkoPost yet: adding fields changes its layout
DepthOfField                     3d.md             # same
Post::lerp                       3d.md             # same; blend PonkoPost fields yourself
PostVolume                       3d.md             # same
NavObstacleShape                 navigation3d.md   # C and C++ obstacles are unturned boxes; ponko_ctx_set_nav_obstacle and its carve variant
ParticleSettings::softness       3d.md             # PonkoParticleSettings3D's layout is fixed; C and C++ particles are drawn hard
Camera::particles                3d.md             # PonkoCamera3D's layout is fixed; C and C++ cameras always draw particles, trails and lines
SkyShader                        3d.md             # C and C++ games use the built-in atmosphere or the flat sky
Ui::set_rich                     ui.md             # not bound yet; labels side by side with their own paint
Ui::set_inline_image             ui.md             # same
Ui::set_inline_font              ui.md             # same
Ui::link                         ui.md             # same; a button for each link
UiEvent::LinkClicked             ui.md             # same
Prediction                       networking.md     # generic over the game's own state and input types; C and C++ games keep their own input history
InputQueue                       networking.md     # same: queue the decoded inputs in C or C++ yourself
Smoothing                        networking.md     # same: fade the correction offset yourself
Physics3D::move_character        physics3d.md      # C and C++ characters walk with the physics step only; no replay of one tick
Net::accept_web                  networking.md     # not bound yet; C and C++ hosts take UDP players only
Net::join_web                    networking.md     # same; C and C++ games don't build for the web yet
Net::web_addr                    networking.md     # same
NetMessages::accept_web          networking.md     # same
NetMessages::join_web            networking.md     # same
NetMessages::web_addr            networking.md     # same
Graphics::load_lights            3d.md             # glTF lights and cameras: read the file's KHR_lights_punctual and cameras yourself; models load with the same extensions
Graphics::load_cameras           3d.md             # same
