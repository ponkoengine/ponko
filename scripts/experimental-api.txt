# Experimental public items: outside the versions' promise.
#
# STABILITY.md, "Maturity levels" and "Unstable": a feature whose guide
# chapter is experimental may change or be removed in any release, without
# a deprecated step first. These are its public items. They keep their
# names (no `unstable_` prefix): instead, scripts/semver-checks.py does not
# count a break of them, and scripts/api-snapshots.py lists them apart, in
# api/<crate>/experimental.txt. C functions among them carry a
# `/* Unstable: ... */` note in include/ponko.h (book/src/c-cpp.md,
# "Unstable functions").
#
# `python3 scripts/experimental-api.py check` keeps this list honest: every
# experimental chapter has a section, every section names an experimental
# chapter, every item still exists, no stable item hands out or takes an
# experimental type, and the C header and C++ wrapper mark exactly the C
# functions listed here. A chapter that becomes tested or proven leaves this
# list in the same pull request (and its items become covered then).
#
# Format:
#   [chapter.md] why the chapter is experimental
#   <item path>    why this item is part of it
#   feature <name> why the cargo feature is unstable
#   web <path>     like an item, for a web-only item the x86_64 listing in
#                  api/ can't show (its existence is not checked)
#   none           the chapter has no public API (say why)
# An item path names a public item as api/ lists it; it covers everything
# under it (a type's fields, methods and impls, a module's items).
